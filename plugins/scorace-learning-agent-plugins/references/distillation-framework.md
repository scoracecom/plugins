# ScorAce 资料蒸馏框架

## 导航

- 统一主链、输入与解析
- 内容覆盖、证据身份与多视角提取
- 质量检查与领域候选
- 用户分工与产物原则

## 目的

把固定原件或已有解析结果转成内容完整、来源可回查、可由人和 Agent 直接使用的领域候选。蒸馏不是摘要，也不是把 OCR 文本套进字段。

## 统一主链

```text
固定用户选择的输入
→ 区分原件、提取运行和派生表示
→ 识别材料角色与适用范围
→ 建立预期结构、处理范围和真实覆盖
→ 按 Profile 从多个视角提取
→ 核对引用蕴含、来源忠实性、学科正确性和关键遗漏
→ 综合为人可读主产物与结构化领域候选
→ 生成引用、质量报告和新版本
```

单份材料可以只贡献当前用途所需的局部领域候选，但本次选择处理的范围必须有覆盖记录。

## 输入与解析

1. 只读取用户明确选择的原件、固定网页快照和解析结果，不扫描相邻目录。
2. 原件按不可变版本登记；OCR、转写或版面解析结果登记为该版本的提取运行与派生表示，不能成为与原件并列的官方来源。
3. 已有可靠解析结果时直接使用。
4. 原件需要 OCR 或版面解析且当前环境提供 MinerU `parse_documents` 时，可以调用它；首次跨越新的外部信任边界前说明发送范围并取得必要授权。
5. MinerU 或其他 Provider 不可用时，要求已有解析结果或明确降级，不能声称已经完成 OCR。
6. Provider 输出、原始 JSON、OCR 块和模型摘要都只是候选。

每个派生表示至少保留原件引用和哈希、提取工具及版本、配置、输入范围、
运行状态、警告与产物哈希；未知配置也要显式记录，不能省略字段。更换解析
结果创建新运行和新包修订，不覆盖旧谱系。

## 候选命令与兼容性

仅在用户明确要求制作或修订候选包时执行候选命令。先运行 `scorace version --json`，确认输出为合法 JSON 且 `protocol` 为 `9`；版本字段只用于诊断。缺少兼容 CLI 时，先检查 Node.js 与 npm，再在用户授权后安装或升级 `@scorace/cli`，最多重试一次。仍不兼容或命令失败时，说明候选生产入口不可用并停止该候选操作，不调用旧独立 Plugin executable。

目标与资料候选分别使用同一 `scorace` executable 的 `scorace distill target ...` 和 `scorace distill material ...` 子命令；参数沿用各自下文的固定工作流。

## 内容覆盖

先建立本次所选范围的预期章节、页段或内容块，再提取语义。覆盖记录至少回答：

- 处理了哪一份来源和哪个页面、章节、区域或段落；
- 该范围预期包含什么，实际是完整、部分、跳过、失败还是未知；
- 内容被采用、仅作背景还是明确排除；
- 它贡献了哪些可寻址内容单元、稀疏语义候选或题目候选；
- 哪些公式、图表、题目、答案或评分依据仍需核对。

只有所有预期范围都有真实处置且不存在未声明缺口时，才能声称本次范围完整。不能用“每个来源都出现过”“已有 `output_refs`”或“已经提取了很多对象”证明没有遗漏；部分成功仍可产生有用产物，但主产物和质量报告必须同步呈现未处理范围。

## 证据身份

严格区分：

- `source_explicit`：来源直接、明确表达；
- `model_organized`：不增加事实，只重新组织来源内容；
- `model_inference`：跨段落或跨材料推导的新结论；

考试 Profile 继续使用 `official | course_or_teacher | past_assessment_observation | model_inference`。资料候选只使用前三种内容身份；模型推断必须保存输入引用和方法。`model_generated` 不属于忠实蒸馏，不能借此加入解释、示例、练习或反馈。

引用摘录必须能在 locator 指定的位置核对，而不只是出现在同一文件的其他位置。结论的表述范围必须由所列引用实际蕴含；由直接证据再推导出的含义拆成 `model_inference`，不能把推断附加在 `official` 或 `source_explicit` 句子中。

## 多视角提取

### 考试目标

- 范围与内容；
- 学生需要表现出的知识、方法和能力；
- 考核方式、题型、作答形式和评分要求；
- 约束、跨材料关系、冲突和未知。

### 教材

- 来源原生结构、顺序与标签；
- 实际出现的概念、命题、方法、任务、解答、答案或关系候选；
- 公式、图表和 OCR 不确定性；
- 无法安全判定的角色、关系或规范映射。

教材 Profile 可以读取一个固定考试目标包。每个连接记录目标包修订、具体目标/要求引用、连接依据、适用范围和 `direct | consistent | model_inference | conflict | unlinked` 状态。没有目标包时教学材料仍可生成，但必须明确标记连接未执行；连接不产生学生状态或正式图谱。

多视角可以由一个 Agent 分轮执行，也可以由多个独立 Agent 执行。输出合同不依赖是否支持 sub-agent。

## 四项质量检查

1. **来源忠实性**：能回到固定位置，转述没有扩大原意。
2. **内容正确性**：公式、答案、表格、推理和关系方向成立。
3. **内容覆盖**：所选范围均有处置，关键结构没有静默丢失。
4. **候选边界**：每个候选能回到来源，明确其内容身份、未知和正式准入缺口。

基础定义或单一权威要求不因只出现一次而被淘汰；“独特性”和“预测力”不是教材或正式规范内容的准入条件。

## 领域候选

结构化产物必须按 [`domain-mapping.md`](./domain-mapping.md) 声明到 ScorAce 规范对象的映射或未映射理由。来源顺序、一般关联和严格前置必须分别表达；关系名称和方向不能由 Provider 自由创造。

包内通过检查不等于对象已经进入正式领域数据。Plugin 不写数据库、不创建正式 `AssessmentGraphRevision`，也不生成学生状态、计分结果或计划。

## 用户与 Agent 分工

Agent 负责提取、核对、建立引用、限定表述、记录不确定性，并按证据设置候选包内状态。包内 `accepted` 只表示通过当前候选包的检查，不写入正式库，也不等于正式领域准入。用户不必逐项审批包内状态；正式准入须按现行合同另行授权和审查。

只有以下情况暂停询问：

- 来源冲突无法由现有证据消解；
- 考试目标或处理范围需要产品取舍；
- 需要新增外部发送权限；
- 需要破坏性覆盖或删除。

## 产物原则

主 Markdown 是内容产品，必须独立可读、具体且可执行。JSON 保存结构化语义，`citations.json` 支撑回查，`quality-report.md` 公开覆盖、警告和未知。

所有成功运行创建新的 `vNNNN` 目录。原件、旧 draft 和旧产物不覆盖；失败运行不留下可被误认成成功的完整版本。

绝对路径只允许保留在本地工作 draft 与 source lock 中，不进入可交换产物。
